# Data policy

Studio stores reviewed-post identity/metadata and provenance, project-specific human labels, audit events, retry receipts, sessions and explicit download journals under its configured data root. Fresh unreviewed query results stay in bounded expiring memory. Browsing media is never retained on server disk; prepared thumbnails use bounded transient RAM caches on the server and client, as described in [media performance](media-performance.md). Plaintext administrator passwords and API keys are not stored in SQLite or returned to the browser.

Raw e621 tags are discovery evidence. Every candidate starts unreviewed. The reviewer confirms positive or negative; tag absence never implies a verified negative. Skip leaves the label unchanged. Undo appends history rather than deleting it.

Images and videos stream privately with no-store responses when browsed or opened. Reviewing never saves media. Double-tap explicitly saves only the original media into the configured collection Inbox; no JSON/TXT/XMP files are written; repeated double-taps are idempotent. The heart button toggles saving/removal, and Downloads Delete cancels an in-progress favourite or removes its completed files. Cancellation cleans only owned download staging; removal verifies exact ownership. Neither changes labels, and clearing a review does not remove saved files. Download thumbnails reuse the existing preview endpoint without storing another copy. Explicit dataset-media export uses the same queue but a separate owned export directory, with checksummed bytes and a reproducible manifest/bundle; favourite deletion cannot delete those exports. Metadata export downloads no originals. Numeric preview fingerprints may be retained for reviewed duplicate analysis, without preview files. Legacy caches and imported-only rows are preserved pending a separate approved cleanup plan. Frozen versions are immutable; unsure/conflicting reviews are excluded from supervision, and never-reviewed query results are absent. No multi-tag training interface is claimed. See [dataset policy](datasets.md).

Use private HTTPS. Authentication protects metadata, media, jobs and metrics. Session cookies are HttpOnly/SameSite Strict, with Secure enabled by default. Mutations require the configured Origin and session CSRF token. Secrets belong in the ignored environment file.

Private passwordless access is optional and disabled by default. With `STUDIO_PASSWORDLESS=true`, anyone allowed through the LAN/VPN proxy can obtain a session automatically. The proxy's network restrictions become the access boundary; session, Origin and CSRF protections still apply.

The owner may explicitly choose private HTTP with `STUDIO_SECURE_COOKIE=false`; transport encryption and certificate verification are then deferred. HttpOnly/SameSite cookies, sessions and Origin/CSRF checks remain enabled.

Media URLs must originate in e621 API responses; clients cannot submit arbitrary fetch URLs. Redirects undergo the same allowlist validation. Studio never modifies e621. Respect the [official API conventions](https://e621.net/help/api) and the rights attached to individual media. Do not redistribute cached media by default.

See [image retrieval and binary-review compatibility](image-retrieval.md) for schema v6, uploads, local vectors, evidence and release gates.

Project deletion removes the target from the workspace immediately and rejects subsequent reads/reviews through its old project URL. Schema v7 records a deletion tombstone for its entire legacy family and removes its canonical mapping. Frozen datasets, audit evidence and shared saved originals remain intact; deletion is not physical data erasure. Recreating the same tag allocates a fresh project with no inherited reviews. Schema upgrades make an online SQLite backup before migration.
