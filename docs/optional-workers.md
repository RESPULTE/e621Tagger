# Optional discovery and laptop work

The owner deferred index downloads and laptop training on 23 October 2026. Home-server review and dataset exports operate without them. P4/P5 transport, training and arbitrary-image embedding retrieval are not implemented or claimed verified by this slice.

Primary-source verification on that date:

- The [Hydra-Embeddings card](https://huggingface.co/datasets/RedRocket/Hydra-Embeddings) describes MessagePack shards named `embeds/e621_static_{post_id // 5000:05d}.hydra35_embed.msgpack`, each with records containing an integer ID and float16 vector. It lists `hydra35_embed_postids.npy` with shape `(6122692,)`, neighbor **post IDs** in `hydra35_embed_ids.npy` with shape `(6122692,64)`, and corresponding distances. Row identity comes from the post-ID array. This supports expansion from indexed IDs, not arbitrary-image KNN.
- The card states that neighbors use L2 distance on mean-centered, unit-normalized vectors. It does not publish the centering vector or an exact reproducible feature-extraction definition. Vector dimension, precise feature layer/pooling and generating checkpoint hash are not established by the card. The sample deserialization code alone is insufficient proof of a working NumPy decoder.
- The [model card](https://huggingface.co/RedRocket/Hydra) and linked [inference.py](https://huggingface.co/RedRocket/Hydra/blob/main/inference.py) expose tag classification. They do not establish a compatible embedding endpoint. Do not assume classifier logits or an arbitrary intermediate tensor equals the published vector representation.

When resuming, first verify local array headers, file checksums and an actual record, then implement a bounded, memory-mapped known-ID neighbor adapter with provenance. Keep the giant files on optional SSD/laptop storage. Verify checkpoint, preprocessing, feature schema and normalization before mixing vectors generated by another path.

The first classifier should consume an immutable reviewed dataset and compatible frozen features, with verified negatives and group-held-out train/validation/test partitions. Fit transforms on train only, select thresholds on validation only, and report precision/recall, AP/PR-AUC, precision@K, calibration and false positives per 100 verified negatives. Empty or one-class splits must fail explicitly. Future laptop polling needs separate scoped authentication, immutable checksummed job/artifact manifests, bounded leases/retries, progress and restart recovery; offline laptop status must not block review. These are acceptance criteria, not a deployed worker.
