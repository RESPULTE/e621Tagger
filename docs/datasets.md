# Dataset versions and quality

P3 adds unrelated and lookalike query provenance, project quality summaries, duplicate grouping, deterministic group splits and immutable versions. No source kind assigns a human label. Previously saved historical imports preserve seed ID, publisher revision/row, row artifact digest, metric and each neighbor’s rank/distance as `provenance[].embedding` in newly frozen manifests. This evidence never changes eligibility or split policy; previously frozen manifests retain their exact bytes. Query pages are transient. Only human-reviewed posts become durable dataset members; legacy unreviewed imports are preserved outside new dataset membership.

## Snapshot contract

`POST /api/projects/{id}/datasets` takes `request_id`, `name`, `split_seed` (default `studio-v1`), `group_artists` (default true), `group_series` (default false), and `near_hamming` (default 4, range 0–8). A short SQLite transaction captures project metadata, each human-reviewed post's label/version/latest event, availability, media URL/MD5, provenance and matching preview fingerprint. Analysis runs off the event loop. A second short transaction publishes the version and idempotency receipt together; concurrent identical retries publish one version. Later reviews cannot mutate a frozen manifest, enforced by database triggers. Reusing a request ID with different inputs returns 409.

The canonical full manifest is UTF-8 JSON with sorted keys and compact separators. Its SHA-256 is stored alongside it and returned as `X-Manifest-SHA256` on exports. The hash covers the **full JSON manifest**, not CSV/JSONL bytes. Each version has a UUID and format `schema_version=1`; split policy is versioned separately. A freeze captures the state when its snapshot read occurs, even if reviews continue during analysis.

`GET /api/projects/{id}/datasets` lists the latest 100 versions. `GET /api/datasets/{uuid}/export?format=json` exports the exact full manifest including excluded samples. `format=jsonl` emits one `type=manifest` metadata line, then `type=sample` lines for supervised examples. `format=csv` emits supervised examples with dataset ID/hash, review versions, URLs/MD5, group/split and JSON provenance. Spreadsheet formula prefixes are escaped. All exports require a session and stay private. These metadata-only exports download no originals and retain null relative media paths. Explicit media exports are described below.

## Eligibility and grouping

- Only human `positive` and `negative` reviews can have targets 1 and 0. Legacy unsure decisions are unreviewed and absent from new manifests; their stored history and old frozen manifests remain unchanged. Never-reviewed discovery results are absent from new manifests. Conflicting duplicate-project reviews remain preserved and excluded from supervision.
- Deleted/unavailable posts, missing original URLs, unsupported media, missing MD5 and missing preview URLs are separate availability states. Still-image originals use JPEG, PNG and WebP. Reviewed GIF/video thumbnails and individually sampled frames export as immutable PNGs; animated WebP/AVIF containers are decoded to distinguish them from still images. Unsupported formats remain explicit exclusions.
- Exact MD5 duplicates use the smallest eligible post ID as their supervised representative. If any positive and negative reviews share an MD5, that exact group is excluded pending review. All original records/provenance remain in the full manifest.
- A 64-bit difference hash is computed from each validated 320px preview derivative: grayscale, Lanczos resize to 9×8, row-wise adjacent-pixel comparisons. Hamming distance ≤4 is the default near-duplicate edge; connected components include transitive edges. Stored fingerprints bind to the source MD5 and preview URL and are retained without preview files.
- Artist grouping links matching artist tags, excluding generic unknown/anonymous/administrative markers. Optional series grouping uses matching **copyright** tags as a conservative proxy, not a canonical series resolver. Shared tags can create large groups.
- The group ID is its smallest post ID. SHA-256 of `seed:post:<id>`, first 32 bits modulo 100, selects train (0–79), validation (80–89), or test (90–99). Known exact/near duplicates and selected artist/series groups cannot cross splits. Ratios are group assignments, not exact row counts; no balancing step breaks groups. New versions can regroup as new candidates/bridges arrive; old manifests remain immutable.

Preview dHash is a heuristic. Crops, edits, composition changes and missing fingerprints among unreviewed bridging posts can escape detection. It can also conservatively merge visually similar but distinct samples. Inspect held-out groups and ambiguous examples before evaluating a classifier; this is not a guarantee against every semantic leak. Frozen availability records metadata at capture time, not a live download guarantee.

## Preparation and bounds

`GET /api/projects/{id}/quality` reports human-label counts, source diversity, availability, exact/known near duplicate groups, contradictory exact labels. Duplicate counts depend on fingerprint coverage. `POST /api/projects/{id}/quality/prepare` queues up to 64 eligible reviewed missing fingerprints through the existing durable preview queue; repeatedly preparing is safe. Failed previews show errors and retain the five-minute retry cooldown. A freeze returns 409 until every otherwise-eligible reviewed sample has a source-matched fingerprint.

The workflow caps projects at 5,000 candidates, manifests at 16 MiB and BK-tree near-hash analysis at one million comparisons. It rejects excess work explicitly instead of freezing an incomplete subset. No full embedding index, GPU or new dependency enters the server runtime.

Schema v4 upgrades v1/v2/v3 additively after an integrity-checked online `pre-schema-v4` backup. It preserves human history, frozen manifests and legacy cache/import records, and adds canonical target/conflict views plus download progress/partial ownership. Display never reuses or rewrites old cache files. A downgrade requires preserving the migrated volume and restoring the pre-upgrade backup to a fresh volume. See [operations](operations.md).

## Explicit media exports and training compatibility

From Tagged, open Dataset & export, freeze reviewed samples, then choose Download dataset media. `POST /api/datasets/{uuid}/media` queues eligible frozen samples through the same download workers as collection saves. Repeated requests reuse the dataset/post intent. This action does not toggle collection hearts or change reviews. Originals publish to `/data/exports/<uuid>/` in the configured data volume, with pinned source MD5, checked length and SHA-256. Deleted or changed originals fail honestly and leave the frozen review/manifest intact.

Downloads shows progress, completion, errors, retry and cancellation for both purposes. An original image is available at `/api/datasets/{uuid}/media/files/{post_id}` and a sampled image at `/api/datasets/{uuid}/media/samples/{sample_id}` only after verified publication. `/media/manifest` returns 409 until every eligible sample has completed and its bytes still match; the returned manifest adds safe relative paths, byte lengths and SHA-256 without mutating the original frozen manifest. `/media/bundle` produces a deterministic ZIP containing exactly these files and `manifest.json`, checks bytes again during packaging, and removes its temporary archive after delivery. Bundles cap at 4 GiB and require temporary free space; larger exports can use the individual files and checked manifest.

These are scalar reviewed-target data exports. The processing-PC [native character trainer](character-training.md) consumes the checked media bundle's `manifest.json` and preserves its frozen splits. It trains one previously absent character tag, not a multi-tag target or replacements for existing heads. `male lugia` can be a discovery query inside an explicitly named target project; it does not verify both component labels. Character recognition quality requires held-out reviewed data; synthetic trainer checks establish plumbing only.

See [image retrieval and binary-review compatibility](image-retrieval.md) for schema v6, uploads, local vectors, evidence and release gates.

Animated posts contribute their reviewed thumbnail as a PNG training sample. Independently reviewed saved frames are additional samples, with their own labels and review versions. Samples from the same source post always share a split; identical image bytes are deduplicated or excluded when labels conflict. Media bundles contain the saved PNG samples and preserve source post identity, without exposing local paths. If a source or saved sample changes after freezing, its media export fails rather than substituting different content.


## Animated-media review

The gallery decision labels the static thumbnail by default. In the expanded viewer, enable frame sampling to seek with the gold cursor; double tap the cursor (or press Enter/Space) to retain a still. Select a checkpoint to review that sample independently. Green/red checkpoints and borders show positive/negative decisions; gold means undecided. The gallery outline and project counters use the majority of reviewed samples, with a neutral tie. Thumbnail and frame samples retain separate decisions, while changing a thumbnail decision also updates the ordinary gallery review.

Double tapping focused sampled media saves that PNG to the configured collection using the same verified, no-clobber publication and owned-file removal as original favourites. Unfavouriting removes the collection copy and keeps the tagging sample. Playing/seeking exits sample focus, so double tapping the video saves the original. Sample hold-search uses its still image bytes, and preserves the existing hold animation and release-to-search behavior.

Samples are source-MD5-bound, version checked, and stored outside the transient preview cache. Up to 256 frames plus the thumbnail per project/artwork are retained. GIF/WebP/AVIF sampling bounds compressed originals to 32 MiB, decoding to 2,000 frames and 200 million total pixels; capture uploads obey the configured reference-image limit. Video sampling uses browser-decoded frames and preserves native playback and automatic MP4 fallback. Old reviewed animations can acquire their thumbnail sample by reviewing again or selecting Thumbnail in the expanded view. Existing frozen manifests remain unchanged.
